# 功能规格：任务打卡与 iPad 使用同页 Tab

## 状态

已批准

## 目标

将任务打卡与 iPad 使用管理整合到同一页面，通过清晰、可访问的顶层 Tab 切换，减少新窗口和返回操作，同时保持两个功能域的数据与交互相互独立。

## 用户故事

- 作为家庭成员，我希望在同一页面切换任务打卡和 iPad 使用，以便快速查看两类日常记录。
- 作为家庭成员，我希望切换 Tab 后保留各自选择的日期和页面状态，避免重复操作。
- 作为任务管理员，我希望任务管理入口只出现在任务打卡页面，避免在 iPad 页面产生功能混淆。

## 范围

### 包含

- 顶部新增“任务打卡”和“iPad 使用”两个带 SVG 图标的 Tab。
- 两个 Tab 在同一浏览器页面切换 `home-view` 与 `ipad-view`。
- 顶部成员信息和切换家人入口在两个 Tab 中持续展示。
- 激励文案从 Tab 所在行拆分为独立轻量信息条。
- 任务管理和添加任务入口移动到任务打卡 Tab 的内容工具栏。
- iPad 使用协议、使用类型管理和添加使用记录位于 iPad Tab 的内容工具栏。
- 手机端采用“成员行、Tab 行、激励行、内容工具栏”的纵向层级。
- 保留旧 `ipadMember` 查询参数的兼容能力；使用旧链接时直接进入 iPad Tab。

### 不包含

- 修改任务、iPad 使用记录、成员或 Supabase 数据结构。
- 修改额度、超时、任务排期或完成状态算法。
- 新增底部导航、手势切换或第三个 Tab。
- 自动部署或执行数据库迁移。

## 功能规则

1. 初次选择成员后默认进入“任务打卡”Tab。
2. 点击 Tab 只能切换可见工作区，不得打开新窗口或新标签页。
3. 当前 Tab 必须通过 `aria-selected` 和可见样式同时表达。
4. Tab 切换时必须保留任务日历的 `selectedDate` 和 iPad 日历的 `ipadSelectedDate`。
5. 在 iPad Tab 切换家人时，沿用既有 iPad 成员切换规则并重置 iPad 选中日期；任务归属不得被修改。
6. 任务管理入口和任务添加入口只在任务打卡工作区出现。
7. iPad 协议、类型管理和添加记录入口只在 iPad 工作区出现。
8. 激励文案继续每 16 秒更新，但位于 Tab 导航之外，不挤压 Tab。
9. 旧 `?ipadMember=<id>` 链接打开时，必须选择对应成员并显示 iPad Tab。

## 响应式与可访问性

- 桌面端顶部使用“成员信息 / Tab / 切换家人”的三列结构。
- 900px 以下成员信息和切换家人在第一行，Tab 独占第二行。
- 560px 以下两个 Tab 等宽，单个触控区域不小于 44×44px。
- 激励信息条在手机端允许标题与副标题分行，不得横向溢出。
- Tab 使用 `role="tablist"`、`role="tab"`、`aria-controls` 和 `aria-selected`。
- 工作区使用 `role="tabpanel"` 和对应的 `aria-labelledby`。
- 键盘焦点样式必须可见，并遵守减少动态效果设置。

## 验收标准

- [x] AC-1：顶部同时展示“任务打卡”和“iPad 使用”两个可访问 Tab，默认选中任务打卡。
- [x] AC-2：点击 iPad Tab 后在当前页面显示 iPad 工作区，不调用 `window.open` 或页面跳转。
- [x] AC-3：切回任务打卡后，任务日历和任务列表恢复原状态。
- [x] AC-4：任务管理与添加任务只出现在任务打卡工作区。
- [x] AC-5：iPad 协议、类型管理与添加记录只出现在 iPad 工作区。
- [x] AC-6：激励文案独立成信息条，并继续每 16 秒更新。
- [x] AC-7：375px、768px、1280px 宽度下无横向滚动，Tab 和关键操作触控尺寸不小于 44px。
- [x] AC-8：旧 `ipadMember` 链接仍能直接进入对应成员的 iPad 工作区。
- [x] AC-9：现有任务、iPad、成员、弹窗和 Supabase 相关测试无回归。

## 数据与安全影响

- 无数据库、RLS、RPC、认证或存储变更。
- 不新增本地数据字段。
- Tab 仅控制现有视图的可见状态。
