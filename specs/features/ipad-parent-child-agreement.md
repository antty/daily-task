# Feature: iPad 使用亲子协议

## Status

Approved

## Goal

让家庭成员在 iPad 使用管理页随时查看结构清晰、规则无歧义的亲子使用协议。

## Scope

### In scope

- 在 iPad 使用管理页标题栏提供协议 SVG 图标入口。
- 点击入口后打开只读、可滚动的协议弹窗。
- 按用户确认的修订版展示前言、5 条使用约定、正常使用超时规则、未经允许使用的处罚规则和补充说明。
- 修正原始规则中的处罚冲突、时间区间重叠和 1–9 分钟规则空白。
- 支持桌面、手机竖屏和手机横屏，并提供完整的键盘与辅助技术标签。

### Out of scope

- 在线签名、确认协议、记录阅读状态或强制同意。
- 保存协议版本、签署日期或签名图片。
- 将附件中的手写姓名、签名或日期录入系统。
- 修改 iPad 额度、计时、超时计算、Supabase 表、RLS、RPC 或缓存数据模型。
- 自动计算、判断或执行协议中的暂停使用处罚。

## User Stories

- 作为家庭成员，我希望在 iPad 使用管理页快速打开协议，以便使用前了解家庭约定。
- 作为家长，我希望正常超时与未经允许使用的处理规则表达清楚，避免对处罚标准产生不同理解。

## Functional Requirements

1. iPad 使用管理页标题栏右侧必须展示协议图标按钮。
2. 手机标题栏必须保持左侧返回、中间标题、右侧协议入口的平衡布局。
3. 协议按钮必须使用 SVG 图标，并提供 `aria-label="查看 iPad 使用协议"` 和可见的键盘焦点。
4. 点击协议按钮必须打开原生 `dialog` 弹窗；关闭按钮和 Escape 均可退出。
5. 弹窗必须展示标题“每日 iPad 使用亲子协议”。
6. 弹窗必须按以下结构展示附件内容：
   - 协议前言；
   - 5 条编号使用约定；
   - 正常使用超时处理表；
   - 未经允许使用的计算说明和处罚表；
   - 家长责任、特殊情况和协议目的三条补充说明。
7. 正常使用超时区间必须依次为 1–60 分钟、61–120 分钟和超过 120 分钟，不得重叠。
8. 未经允许使用的处罚区间必须依次为 1–9 分钟、10–60 分钟、61–120 分钟和超过 120 分钟；1–9 分钟只提醒，不记录违规次数。
9. “未经允许使用时长”必须明确表达为“iPad 系统记录的当日使用总时长 − 习惯养成系统当日登记的使用时长”，并注明结果小于 0 时按 0 分钟计算。
10. 协议弹窗只展示规则，不自动计算未经允许使用时长，也不创建、修改或删除任何本地或云端数据。

## Protocol Content

### 标题与前言

- 标题：每日 iPad 使用亲子协议
- 前言：为了让 iPad 成为学习和娱乐的好帮手，也为了保护眼睛、保证作息、培养自律和健康习惯，我们一起订立以下约定。

### 使用约定

1. iPad 平时由家长保管，小朋友不能自行取用。
2. 每次使用 iPad，必须在吃完饭 30 分钟后才能开始。
3. 每次开始使用 iPad 时，需要在系统中登记开始时间。
4. 到达约定使用时间后，小朋友应主动停止使用，并将 iPad 交还给家长。
5. 如果当日累计计入时长超过约定时间，则按照以下规则处理。

### 正常使用超时处理规则

| 超时时长 | 处理方式 |
| --- | --- |
| 超时 1–60 分钟 | 记录违规 1 次；累计违规超过 3 次，暂停使用 1 天 |
| 超时 61–120 分钟 | 暂停使用 2 天 |
| 超时超过 120 分钟 | 暂停使用 1 周 |

### 未经允许使用的处罚规则

未经家长允许使用 iPad 时，根据未经允许使用的时长进行阶梯处理。

**未经允许使用时长 = iPad 系统记录的当日使用总时长 − 习惯养成系统当日登记的使用时长**

如果计算结果小于 0，则按 0 分钟计算。

| 未经允许使用时长 | 处理方式 |
| --- | --- |
| 1–9 分钟 | 进行提醒，不记录违规次数 |
| 10–60 分钟 | 暂停使用 1 天 |
| 61–120 分钟 | 暂停使用 2 天 |
| 超过 120 分钟 | 暂停使用 1 周 |

### 补充说明

- 家长应公平、稳定地保管和交接 iPad，并协助记录使用时间。
- 如果有外出、假期或学习任务等特殊情况，可由家长和小朋友提前商量，临时调整。
- 本协议不是为了惩罚，而是为了帮助小朋友学会安排时间、遵守约定和保护身体。

## Data and Security Impact

- 无。
- 协议内容为静态只读文本，不读取 iPad store，不新增网络请求。
- 不存储附件、协议内容、阅读状态、签名或个人信息。

## UX and Failure Behavior

- 桌面弹窗宽度不超过 680px，高度不超过可视区域，正文区域可滚动。
- 手机弹窗按现有移动端 sheet 规范展示，保留安全区和明确关闭入口。
- 标题与关闭操作保持可见；长正文不得导致页面主体横向滚动。
- 两组处罚规则必须使用语义表格，不仅依赖颜色表达。
- 计算公式在窄屏下必须允许安全换行，不得造成横向溢出。
- 协议入口和关闭按钮的触控区域不得小于 44×44px。

## Constraints

- 保持原生 HTML、CSS 和 ES Module 架构。
- 复用现有 `manager-dialog`、`dialog-head`、`dialog-body` 和关闭事件机制。
- 不引入第三方依赖。
- UI 资源变更必须更新统一缓存版本。
