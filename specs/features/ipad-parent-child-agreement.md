# Feature: iPad 使用亲子协议

## Status

Approved

## Goal

让家庭成员在 iPad 使用管理页随时查看结构清晰、额度动态更新的亲子使用协议。

## Scope

### In scope

- 在 iPad 使用管理页标题栏提供协议 SVG 图标入口。
- 点击入口后打开只读、可滚动的协议弹窗。
- 将附件中的协议正文整理为说明、12 条约定、超时处理表和补充说明。
- 将协议中的每日娱乐额度动态替换为当前成员今天设置的 iPad 使用额度。
- 当今天未创建额度时，使用“以当天设置的娱乐额度为准”作为替代文案。
- 支持桌面、手机竖屏和手机横屏，并提供完整的键盘与辅助技术标签。

### Out of scope

- 在线签名、确认协议、记录阅读状态或强制同意。
- 保存协议版本、签署日期或签名图片。
- 将附件中的手写姓名、签名或日期录入系统。
- 修改 iPad 额度、计时、超时计算、Supabase 表、RLS、RPC 或缓存数据模型。

## User Stories

- 作为家庭成员，我希望在 iPad 使用管理页快速打开协议，以便使用前了解家庭约定。
- 作为家长，我希望协议中的每日娱乐额度与今天为该成员设置的额度一致，避免纸面数字与系统配置冲突。

## Functional Requirements

1. iPad 使用管理页标题栏右侧必须展示协议图标按钮。
2. 手机标题栏必须保持左侧返回、中间标题、右侧协议入口的平衡布局。
3. 协议按钮必须使用 SVG 图标，并提供 `aria-label="查看 iPad 使用协议"` 和可见的键盘焦点。
4. 点击协议按钮必须打开原生 `dialog` 弹窗；关闭按钮和 Escape 均可退出。
5. 弹窗必须展示标题“每日 iPad 使用亲子协议”。
6. 弹窗必须按以下结构展示附件内容：
   - 协议说明；
   - 12 条编号约定；
   - 3 档超时处理表；
   - 家长责任、特殊情况和协议目的三条补充说明。
7. 协议顶部说明、第 1 条、第 9 条和第 10 条中的额度必须读取当前成员今天的 `ipad_daily_limits.limit_minutes`。
8. 今天没有额度时，上述位置必须展示“以当天设置的娱乐额度为准”，不得展示 `0`、空白或历史日期额度。
9. 切换 iPad 日历的历史日期不得改变协议额度；协议始终表达今天的约定。
10. 协议弹窗只读，不创建、修改或删除任何本地或云端数据。

## Protocol Content

### 标题与说明

- 标题：每日 iPad 使用亲子协议
- 摘要：每日娱乐总时长为动态额度；iPad 由家长保管；使用原因与时间均需登记。
- 前言：为了让 iPad 成为学习和娱乐的好帮手，也为了保护眼睛、保证作息、培养自律和健康习惯，我们一起订立以下约定。

### 约定

1. 每天 iPad 娱乐使用总时间为动态额度。
2. iPad 平时由家长保管，小朋友不能自行取用。
3. 如果未经家长同意私自拿取并使用 iPad，一经发现，暂停使用 iPad 3 天。
4. 每次使用 iPad 前，小朋友需要先向家长申请。
5. 每次申请使用 iPad 时，需要说明使用原因，并在登记表中记录。
6. 每次使用 iPad 必须在吃完饭 30 分钟后才能开始。
7. 每次开始使用时，需要登记开始使用时间。
8. 当天 iPad 娱乐使用总时间，以每次登记的计入时长累计计算。
9. 学习使用 iPad 不计入动态娱乐额度，但仍需申请、登记和归还。
10. 拼豆需要 iPad 提供图纸时，登记原因为“拼豆图纸”，不计入动态娱乐额度，但仍需申请、登记和归还。
11. 到达约定时间后，小朋友应主动停止使用，并把 iPad 交还给家长。
12. 如果计入时长累计超过约定时间，按照超时规则处理。

### 超时处理

| 超时情况 | 处理方式 |
| --- | --- |
| 超时 1–60 分钟 | 违规记 1 次；累计超过 3 次，暂停使用 1 天 |
| 超时 60–120 分钟 | 暂停使用 2 天 |
| 超时超过 120 分钟 | 暂停使用 1 周 |

### 补充说明

- 家长应公平、稳定地保管和交接 iPad，并协助记录使用时间。
- 如果有外出、假期或学习任务等特殊情况，可由家长和小朋友提前商量，临时调整。
- 本协议不是为了惩罚，而是为了帮助小朋友学会安排时间、遵守约定和保护身体。

## Data and Security Impact

- None。
- 协议只读取当前 store 中当前成员今天的额度，不新增网络请求。
- 不存储附件、协议内容、阅读状态、签名或个人信息。

## UX and Failure Behavior

- 桌面弹窗宽度不超过 680px，高度不超过可视区域，正文区域可滚动。
- 手机弹窗按现有移动端 sheet 规范展示，保留安全区和明确关闭入口。
- 标题与关闭操作保持可见；长正文不得导致页面主体横向滚动。
- 超时处理必须使用语义表格，不仅依赖颜色表达。
- 今天尚未创建额度时，协议仍可正常打开并使用替代文案。
- 协议入口和关闭按钮的触控区域不得小于 44×44px。

## Constraints

- 保持原生 HTML、CSS 和 ES Module 架构。
- 复用现有 `manager-dialog`、`dialog-head`、`dialog-body` 和关闭事件机制。
- 不引入第三方依赖。
- UI 资源变更必须更新统一缓存版本。
