# 任务打卡与 iPad 使用同页 Tab 设计

## 设计结论

采用已确认的视觉稿 v2：以同页双 Tab 作为唯一顶层功能导航，成员上下文持续可见，激励文案与 Tab 分层展示。

## 信息架构

```text
页面
├── 顶部应用栏
│   ├── 当前成员
│   ├── 任务打卡 / iPad 使用 Tab
│   └── 切换家人
├── 独立激励信息条
└── 当前工作区
    ├── 任务打卡
    │   ├── 任务管理 / 添加任务
    │   ├── 任务日历
    │   └── 当日任务
    └── iPad 使用
        ├── 使用协议 / 类型管理 / 添加记录
        ├── 额度摘要
        ├── 使用记录
        └── iPad 日历
```

## 组件边界

- `workspace-tabs`：负责 Tab 语义、选中态和工作区显隐。
- `home-view`：保留任务日期、任务列表和任务管理入口。
- `ipad-view`：保留 iPad 日期、额度、记录、日历和专属管理入口。
- `daily-motivation`：继续独立轮播，不参与导航布局。
- `member-switch`：根据当前工作区选择现有任务或 iPad 成员切换流程。

## 状态与交互

- 新增内存状态 `activeWorkspace`，取值为 `tasks` 或 `ipad`。
- `showWorkspace(name)` 统一更新 Tab 的 `aria-selected`、两个工作区的 `hidden` 状态和对应渲染。
- 默认值为 `tasks`；旧 `ipadMember` 查询参数存在时初始化为 `ipad`。
- Tab 切换不修改 `state.selectedDate` 或 `state.ipadSelectedDate`。
- iPad Tab 不再调用 `window.open`、`location.assign` 或独立返回按钮。

## 响应式布局

- ≥901px：应用栏三列，Tab 居中；激励信息条独立置于下方。
- 561–900px：成员和切换家人在第一行，Tab 占满第二行。
- ≤560px：Tab 等宽；内容工具栏操作缩为图标或短标签；激励标题和副标题分行。
- 所有按钮保持至少 44px 触控区域，无横向滚动。

## 动效

- Tab 内容切换使用 180–260ms 的透明度与纵向位移动效。
- 使用 `prefers-reduced-motion` 时关闭非必要动效。

## 兼容与错误处理

- 保留 `ipadMember` 参数作为旧链接入口。
- 当前成员不存在时仍走既有成员选择弹窗。
- iPad 数据未加载时继续使用既有同步提示和本地回退。

## 测试策略

- UI 结构测试：Tab 语义、入口归属、移动端布局、统一缓存版本。
- 脚本契约测试：同页切换、无新窗口、旧链接兼容和状态保留。
- 完整执行 `node --test`。
- 浏览器验证 375px、768px、1280px，分别切换两个 Tab、切换成员和打开主要弹窗。

## 自查

- 无待定项或占位符。
- 不改变数据模型和领域算法。
- 任务管理只属于任务 Tab，iPad 管理操作只属于 iPad Tab。
- 与用户确认的视觉稿 v2 一致。
