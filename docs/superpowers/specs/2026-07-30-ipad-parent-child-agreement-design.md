# iPad 使用亲子协议设计

## 设计目标

在不改变 iPad 额度与计时业务的前提下，为家庭成员提供一个易发现、易阅读、适合手机操作的协议入口。协议内容来自用户提供的纸质附件，固定规则结构化展示，娱乐额度使用当前成员今天的系统配置。

## 选择方案

采用方案 A：协议入口位于 iPad 使用管理页标题栏右侧。

- 桌面端：标题与协议图标位于同一标题栏，协议按钮作为次要操作。
- 手机端：标题栏保持三列结构，左侧返回、中间标题、右侧协议图标。
- 不将入口放在“使用类型管理”旁，避免用户误认为协议属于管理配置。
- 不将协议内联到页面，避免增加主页面高度和干扰计时任务。

## 组件设计

### 协议入口

- 使用语义化 `button` 和线性 SVG 文档图标。
- 按钮 ID：`open-ipad-agreement`。
- 辅助技术名称：`查看 iPad 使用协议`。
- 视觉层级低于“添加使用记录”，但触控区域保持 44×44px。

### 协议弹窗

- 使用原生 `dialog`，ID 为 `ipad-agreement-dialog`。
- 复用现有 `manager-dialog`、`dialog-head`、`dialog-body` 和 `dialog-close-icon`。
- 正文使用独立的 `.ipad-agreement-content` 滚动区域。
- 正文包含摘要卡片、前言、有序列表、语义表格和补充说明。
- 桌面最大宽度 680px；移动端沿用现有 sheet 规则和安全区。

## 数据流

```text
用户点击协议图标
  -> 读取 store.getIpadState()
  -> 以 state.memberId + today 查找 ipad_daily_limits
  -> 得到 limitMinutes 或替代文案
  -> 更新协议内 4 个 data-ipad-agreement-limit 节点
  -> ipad-agreement-dialog.showModal()
```

- 动态额度只读取当前成员今天的数据。
- `state.ipadSelectedDate` 不参与协议额度计算。
- 协议打开、关闭均不调用 store 写入 API。
- 今天无额度时，使用“以当天设置的娱乐额度为准”。

## 附件内容处理

- 录入打印正文，不录入手写姓名、签名和日期。
- 修复照片透视和折痕造成的换行，不改变条款含义。
- 照片底部被裁切的特殊情况句子按上下文整理为“可由家长和小朋友提前商量，临时调整”。
- 纸面固定的 180 分钟在摘要、第 1、9、10 条中替换为动态额度。

## 错误与空状态

- 今天未设置额度不是错误，协议正常展示替代文案。
- iPad 数据仍在加载时使用同一替代文案，不阻止协议阅读。
- 弹窗不依赖网络请求，因此不会新增网络错误状态。

## 安全与隐私

- 不上传或保存附件图片。
- 不录入手写签名、姓名或执行日期。
- 不新增 Supabase 表、RPC、RLS、Storage 或本地缓存键。
- 只读取已授权家庭的现有 iPad store 状态。

## 测试策略

- TDD 添加结构测试，先验证协议入口、弹窗和完整内容缺失时失败。
- 添加额度渲染契约测试，验证只按 `today` 查找额度，并提供无额度替代文案。
- 添加 CSS 契约测试，覆盖 44px 入口、680px 弹窗、滚动正文和移动端布局。
- 更新统一静态资源缓存版本并运行完整 `node --test`。
- 浏览器手动验证桌面、375×700 和 700×375。

## 验收边界

- 本次仅提供查看协议功能。
- 不要求用户同意协议，不记录查看状态。
- 不实现协议编辑、版本管理、电子签名或处罚自动执行。
